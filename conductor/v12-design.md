# v12 consistency release design

Authorised scope: four work packages from the preceding diagnostic review; preserve default effects and resource prices. The new configuration points to the existing parameter file and a clearly designated live pathway configuration. Historical data/v6/spec.json stays a reference snapshot, not a live configuration input. A site ownership table replaces the inconsistent global-incumbent budget interface for the current regional run. No new simulation engine or decision ML.

Current artifacts live under outputs/v12 with a manifest and resolved-input snapshot. Historical outputs are never silently overwritten. Reporting is derived from current CSV/JSON; broader archival material stays available but is not automatically part of the current deliverable. An execution fingerprint and separate artifact/test-dependency fingerprint bind the final assurance run to actual source and outputs.

Trade-offs: adding an explicit configuration adapter is preferable to a broad rewrite; preserving default results is preferable to refitting unobserved clinical effects. The current reporting path can be minimal and portable; old host-specific builders stay historical. No new dependency is considered installed merely because declared. Runtime and candidate versions are reported separately.

Further review items: repeated consultations versus distinct infants; pairwise mixed deployment; prospective case review; feasible technology eligibility; uncertain funding flows; long-term disability and caregiver consequences. These need bounded methods/inputs and are not invented in this release.

Stopping rules: finish supported repairs and reproducibility checks; missing network/credentials, protected originals, unacquired papers, Gitleaks and independent review stay open. Do not repeatedly reconcile all historic tracks. Reconcile affected predecessors once, then the four new tracks.
