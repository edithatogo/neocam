# Engineering rigour implementation plan

Goal: keep the model frozen while raising the engineering floor — every declared
dependency used at the top of its scope, the test suite deepened, and the static
analysis widened, with evidence for each change.
Spec: spec.md and ../../v14-design.md.
Workflow: conductor-implement then conductor-review; keep records. One revertable commit
per task. Do not change model numbers, clinical parameters or published outputs.

## Phase/task 1.1: Incorporate reportlab with a real artefact
Files: `scripts/build_documents_v4.py` or a new `scripts/build_memo_pdf.py`; `tests/`; `evidence/dependency_targets_v3.json` (only if the declared set changes).
Interface: `reportlab` produces a paginated PDF document that no other tool in the stack produces better; the artefact is registered like the other generated documents.
Acceptance: the PDF is generated by reportlab (not matplotlib), is byte-stable for a fixed input, carries the same disclosed caveats as its DOCX/markdown sibling, and has a test that fails if reportlab stops being used. If the artefact duplicates an existing document with no added value, record that finding and re-open D1 instead of keeping a dead dependency.

- [ ] 1.1.a Write reproducing test(s) for this contract.
- [ ] 1.1.b Run `python -m pytest tests -q -k "report or document"`; preserve expected red evidence (or documented configuration-only inspection).
- [ ] 1.1.c Implement the minimal reportlab renderer; do not modify scientific inputs.
- [ ] 1.1.d Run scoped tests and dependent regressions; preserve actual green output.
- [ ] 1.1.e Review diff, apply evidenced fixes, commit and record SHA in progress.md.

## Phase/task 1.2: Testing depth
Files: `pyproject.toml`; `tests/`; `quality/`.
Interface: pytest-socket (no test may reach the network), pytest-timeout (bounded tests), pytest-randomly (order independence), time-machine (deterministic clock), doctest execution for the modules that now carry examples.
Acceptance: each addition is trialled behind its own commit with the full suite green; a test that depends on network, wall-clock time or ordering fails rather than passing by luck. Exemptions (e.g. the source-retrieval tool's own tests) are documented per-file, never blanket.

- [ ] 1.2.a Write reproducing test(s) for each contract, or document why a configuration-only inspection is the honest evidence.
- [ ] 1.2.b Run the suite with each addition enabled; preserve red evidence where a real gap is found.
- [ ] 1.2.c Implement the minimal change; do not weaken any existing assertion.
- [ ] 1.2.d Run the full suite and the quick profile; preserve actual green output.
- [ ] 1.2.e Review diff, apply evidenced fixes, commit and record SHA in progress.md.

## Phase/task 1.3: Static-analysis depth
Files: `pyproject.toml`; `tests/`; quality gates as needed.
Interface: architecture/import contracts (tach or import-linter), artefact snapshot regression (syrupy or pytest-regressions), dead code (vulture), declared-but-unused dependencies (deptry), and a PII check for the public repository.
Acceptance: every new gate has a specific uncovered failure it addresses (recorded in the commit); thresholds are not lowered; the PII check must not flag the published aggregate facility data as personal data, and must fail on a synthetic identifier fixture.

- [ ] 1.3.a Write reproducing test(s)/fixtures for each gate, including a synthetic PII fixture.
- [ ] 1.3.b Run each candidate tool; preserve the real output that justifies adding it.
- [ ] 1.3.c Implement the minimal addition; no overlapping scanner without a recorded gap.
- [ ] 1.3.d Run the full suite and the quick profile; preserve actual green output.
- [ ] 1.3.e Review diff, apply evidenced fixes, commit and record SHA in progress.md.

## Phase/task 1.4: Experimental features of installed dependencies
Files: `pyproject.toml`; `quality/cli.py`; document/report scripts; `scripts/analyse_v5.py` (optional).
Interface: verified-available features only — `COVERAGE_CORE=sysmon`, `matplotlib.typing` (replacing the untyped-kwargs suppressions), `pip-audit --vulnerability-service=osv`, `uv pip check`/`uv export`, hypothesis `target()`/`event()` plus a seeded non-derandomised profile, `--gremlin-batch`, and optionally scipy `qmc.Sobol(optimization=...)` and `sklearn.frozen.FrozenEstimator`.
Acceptance: each trial measured before/after (runtime, findings, suppressions removed); any trial that loses more than it gains is reverted and recorded.

- [ ] 1.4.a Record the baseline for each trial (runtime, finding counts, suppression count).
- [ ] 1.4.b Apply one trial at a time; preserve the measured delta.
- [ ] 1.4.c Revert any trial that does not pay for itself, with the measurement as evidence.
- [ ] 1.4.d Run the full suite, the quick profile and the affected gate; preserve green output.
- [ ] 1.4.e Review diff, apply evidenced fixes, commit and record SHA in progress.md.

## Phase/task 1.5: Custom-validation replacement spike (harness only)
Files: `quality/contracts.py` (spike only).
Interface: evaluate `msgspec` (or pydantic v2) as a replacement for the bespoke
shape-validation and TypedDict/cast scaffolding, measured against the current code.
Acceptance: a time-boxed spike with measured LOC removed, error-message compatibility
(the suite asserts messages), dependency-size impact, and a written recommendation. Do
not merge the spike into the model; if adopted, it is its own track with its own review.

- [ ] 1.5.a Measure the current harness validation surface (LOC, suppressions, test couplings).
- [ ] 1.5.b Build the spike off to the side; do not disturb the passing tree.
- [ ] 1.5.c Record measured tradeoffs against D1/D4 criteria (value per dependency).
- [ ] 1.5.d Report the recommendation with evidence; do not merge unprompted.
- [ ] 1.5.e Record the outcome in progress.md and in v14-design.md.
